1 · Architecture decisions already taken

DecisionWhy it is fixed
Postgres as the single spineNo Kafka, no microservices, no vector store. Every workflow is an explicit state machine over tables. Production precedent: a 43M-row job queue already runs this way.
Append-only events ledgerEvery other table's changes emit here. The UI and analytics are projections of it; it doubles as the audit record. No update or delete grants.
Owned work lives in actionsA signal that nobody owns is not a feature. Every action carries evidence, an assignee, an SLA and a mandatory reason on dismissal.
Three-tier intelligenceT0 deterministic rules over the ledger (most of it), T1 schema-validated LLM calls through one gateway with a named fallback, T2 nightly aggregate reasoning behind an experiment gate. AI never computes a client's money.
Thresholds live in rules_registryChanging a threshold is a versioned, audited edit — never a deploy. Section 4 lists them all.
Provenance on every figureEach number is tagged computed, rule or learned and can name its own source. This is a product requirement, not a debug aid.

Means: Gains already realised this financial year, and gains still unrealised, each split into long and short term.

Return (XIRR)xirrcomputed

Means: The annualised return on the actual timing of the money, not a simple gain percentage.

How a user reads it: Always compared against the same period's benchmark shown beside it. Ahead or behind that is what matters, not the absolute number.

Derivation: Cash-flow XIRR over the client's own dated flows plus today's value. Never an average of per-holding XIRRs.

Caveat: Holdings under a year are not annualised — a short holding shows no XIRR rather than a misleading one.
